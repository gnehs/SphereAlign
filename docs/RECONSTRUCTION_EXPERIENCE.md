# 對齊、遮罩與分塊重建經驗整合

此整合依據提供的四份重建／tile 修復紀錄，將可重用的流程與檢查加入 APP。實驗版本的局部改善不代表其他拍攝一定適用；APP 保留可調參數、輸出來源紀錄與目視驗收提示。

## 在 APP 使用

1. **遮罩**：預設排除鏡頭邊緣與機身，可單獨使用而不載入偵測模型。「遮罩細部設定」可調信心門檻、四方向偵測與擴張像素。
2. **人多場景**：按「套用人多場景設定」，啟用人物、四方向與 2 推論像素擴張。原生魚眼門檻為 0.50；五個校準視角為 0.10。切換偵測模式後可重新套用。這是待檢查的起點，不能保證消除漏遮或誤遮。
3. **校準透視視角**：選擇同一批拍攝的 COLMAP 文字模型資料夾，內含 `cameras.txt` 與 `images.txt`。程式按 `lensN/sourceNNN` 對應相機，檢查 OPENCV_FISHEYE 校準及原始尺寸，不猜 camera ID、不縮放內參。首次專案可先做原生遮罩與對齊取得校準，再重跑遮罩與對齊。
4. **人工補遮罩**：選擇含 `lens0/source000_00000001.png` 等檔案的資料夾。PNG 必須為原始尺寸的 L8 二值影像，白色保留、黑色排除；額外黑色區域與生成遮罩取聯集。未提供額外檔案的影格照常處理。
5. **對齊**：鄰近影格配對預設 5，可設 2–30，以每段拍攝的已選取實體影格計數。困難區段可試 15，重新比較逐來源覆蓋率與幾何品質。原有條件式配對／救援邊仍保留，範圍並非所有候選邊的硬上限。
6. **品質**：對齊後在任務詳情查看「重建品質」。既有完成或失敗的專案可按「檢查既有模型」，僅重新匯出文字模型與檢查資料，不執行 SfM 或改變相機姿態。需有 `sparse/0`、原生影像與相符的 COLMAP 資料庫。

## 經驗如何落地

| 紀錄中的問題 | APP 行為與界線 |
| --- | --- |
| 低門檻原生四方向把牆、柱子當人物 | 原生與透視預設分開；遮罩報告標記排除 ≥60%／≥90% 的候選影像供檢查，不自動判定誤遮 |
| 透視影像套魚眼圓形邊界、forward splat 產生洞 | 使用五張 640×640、100° FOV 視角，中心及 yaw/pitch ±60°；完整正方形推論後 inverse gather 回原生像素，最後組合光學與人工排除區域 |
| 舊筆記把 v57 寫成原生 conf 0.5 | 以實際 producer 為準：五校準視角、四方向、conf 0.10、tile dilation 2；保留原生模式供不同場景比較 |
| 重跑只檢查 PNG 尺寸，混用新舊遮罩 | 每張 PNG 旁保存 receipt，包含影像、模型、設定、額外遮罩、輸出 SHA-256。重跑遮罩需內容與二值格式均一致才重用 |
| 新遮罩下仍使用舊特徵或混合 keypoint 索引 | 對齊前驗證輸入及遮罩設定；既有 fingerprint 使遮罩異動後的特徵失效。最終逐觀測核對同一資料庫的 keypoint 座標與 point track 雙向索引；不一致時對齊階段失敗並保留報告 |
| 配對圖連通，某段實際註冊仍很少 | 逐拍攝來源計算完整 rig 覆蓋、連續缺口、觀測不足影格；不以全體平均掩蓋局部失敗 |
| 同鏡頭回環漏掉相機轉向後的相反鏡頭 | 回環檢索納入兩個鏡頭，候選仍交由幾何驗證 |
| 低重投影誤差仍出現房間折疊、重影、跨來源比例差 | 顯示原生像素誤差、遮罩內觀測、路徑跳點候選，報告只標示「發現問題」或「需要目視驗收」，不自動宣告場景正確 |
| 獨立 tile SfM 或未錨定局部模型硬合併 | APP 維持全域對齊；訓練檢查表要求共用姿態與內參、完整 rig、halo 訓練／core 裁切、points 座標系與原視角評估 |
| 顯示比例被當成實體尺度修正 | 檢查表明確分開顯示縮放與實體校準；IMU 姿態改善不作為尺度已正確的證據 |
| 任意 seek 補影格造成名稱相同、內容不同 | 維持既有從頭解碼及選取序號的第二階段抽幀；檢查成對名稱、尺寸與選取時間序，不新增任意 seek 補圖捷徑 |

## 診斷門檻與輸出

- `metadata/mask_run.json`：有效設定、遮罩完成／驗證數量、過度排除候選；`masks/**/*.png.receipt.json` 保存逐影像來源。改變外部校準、模型或人工遮罩檔案後，應先重跑遮罩。
- `metadata/pair_policy.json`：配對範圍、實際候選數量與計數單位。
- `metadata/reconstruction_quality.json`：逐來源完整 rig 覆蓋與最長缺口、原生 median/P95/max 誤差、排除區域中的舊觀測、特徵與 track 一致性、弱影格及孤立路徑跳點候選。
- 覆蓋 85%、原生誤差 4 px、每 rig 至少 30 個有效觀測，是篩檢門檻，不是訓練驗收標準。路徑跳點是相對來源中位移動量的啟發式候選，不據此自動刪相機。
- 品質報告記錄模型、資料庫及 WAL、影像、遮罩的檔案大小與修改時間。讀取時若異動會標記過期；這是本機異動偵測，不是密碼學完整性保證。
- 像素遵循 COLMAP corner 座標系：第 `(x,y)` 個像素中心為 `(x+0.5,y+0.5)`。參考 [COLMAP FAQ](https://colmap.github.io/faq.html) 與 [相機模型文件](https://colmap.github.io/cameras.html)。

## 尚未自動化

完整 LichtFeld／Spirula 分塊訓練、語意誤遮的人工繪製介面、門框與牆面目視驗收、跨來源尺度修復仍需外部工具或人工核對。此變更新增的是遮罩處理、對齊配對與品質檢查，以及分塊訓練前的檢查指引；不會把外部實驗訓練包裝成已內建的一鍵流程。
